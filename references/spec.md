# Specification

Synthesize settled context into a durable handoff. Do not start another interview or approval loop.

1. Inspect relevant code, terminology, ADRs, contracts, and existing tests.
2. Describe behavior and boundaries rather than volatile file-level steps.
3. Prefer existing test seams. Name a new seam only when observable behavior cannot be verified through an existing one.
4. Write only the sections that carry useful information:
   - Problem
   - Outcome
   - Decisions
   - Acceptance Criteria
   - Testing
   - Deferred or Out of Scope
   - Open Risks
5. Make acceptance criteria observable and individually checkable.
6. Preserve unresolved risks explicitly; do not convert them into invented decisions.
7. Draft locally or return the document in the conversation. Publish externally only when the user explicitly requests and authorizes it.

Do not generate exhaustive user-story inventories, code snippets, detailed file plans, or tracker metadata by default.
